# Техническое задание - Frontend
## Сервис мониторинга здоровья сервисов X-Lab Status Service
### Frontend (React + TypeScript)

---

## 1. Общие сведения

### 1.1. Назначение документа
Настоящее техническое задание определяет требования к разработке frontend части сервиса мониторинга здоровья сервисов и отображения временной шкалы их состояний для экосистемы X-Lab.

### 1.2. Цель проекта
Создание современного веб-приложения для:
- Визуализации текущего состояния здоровья всех сервисов
- Отображения исторической информации о состояниях сервисов на временной шкале
- Предоставления публичного доступа к общей информации о здоровье системы
- Обеспечения приватного доступа к детальной информации для авторизованных пользователей
- Управления конфигурацией мониторинга (для администраторов)

### 1.3. Область применения
Frontend приложение предназначено для использования:
- DevOps-инженерами для мониторинга инфраструктуры
- Разработчиками для отслеживания состояния зависимых сервисов
- Менеджментом для получения общей картины доступности системы
- Клиентами для просмотра публичного статуса сервисов

## 2. Функциональные требования

### 2.1. Режимы доступа

#### 2.1.1. Public Dashboard (Публичный режим)
- **Доступ**: Без авторизации, открытый доступ
- **Маршрут**: `/`
- **Функциональность**:
  - Общий обзор состояния всех публичных сервисов
  - Индикаторы состояния (цветовая индикация: зеленый/желтый/красный)
  - Счетчики метрик (общее количество сервисов, количество проблемных)
  - Общий статус системы
  - Время последнего обновления
  - Минималистичный дизайн, оптимизированный для быстрой загрузки
  - Автоматическое обновление данных (polling или SignalR)
- **Ограничения**:
  - Нет детальной информации о сервисах
  - Нет истории состояний
  - Нет метрик производительности
  - Нет возможности управления
  - Отображаются только сервисы с флагом IsPublic = true

#### 2.1.2. Private Dashboard (Приватный режим)
- **Доступ**: Требуется авторизация
- **Маршрут**: `/dashboard`
- **Функциональность**:
  - Полный обзор состояния всех сервисов с деталями
  - Индикаторы состояния с дополнительной информацией
  - Расширенные счетчики метрик
  - Последние события и уведомления
  - Фильтрация и поиск сервисов
  - Группировка по тегам или типам
  - Real-time обновления через SignalR
  - Экспорт данных

#### 2.1.3. Детальная информация о сервисе (Private)
- **Маршрут**: `/services/:id`
- **Требует**: Авторизация (роль Viewer или Admin)
- **Функциональность**:
  - Текущее состояние и метрики производительности
  - Временная шкала состояний с возможностью масштабирования
  - История инцидентов с деталями
  - Конфигурация проверок (для роли Admin)
  - Графики метрик (время отклика, доступность)
  - Логи ошибок (для роли Admin)
  - Фильтрация по периоду времени
  - Экспорт истории

#### 2.1.4. Администрирование (Private, роль Admin)
- **Маршрут**: `/admin`
- **Требует**: Роль Admin
- **Функциональность**:
  - Управление списком мониторируемых сервисов
    - Добавление нового сервиса
    - Редактирование существующего сервиса
    - Удаление сервиса
    - Включение/отключение мониторинга
    - Настройка публичности (IsPublic)
  - Настройка параметров проверок
  - Управление уведомлениями и webhooks
  - Настройка периодов хранения данных
  - Управление пользователями и ролями
  - Настройка системы

#### 2.1.5. Аутентификация
- **Маршрут**: `/login`
- **Функциональность**:
  - Форма входа (username/password)
  - Валидация полей
  - Обработка ошибок аутентификации
  - Сохранение токена
  - Автоматическое обновление токенов через refresh token
  - Редирект на защищенные маршруты после успешного входа
- **Защищенные маршруты**:
  - Проверка токена перед доступом
  - Редирект на `/login` при отсутствии авторизации
  - Проверка ролей для административных маршрутов

### 2.2. Временная шкала состояний

#### 2.2.1. Визуализация
- Отображение изменений состояний сервисов на временной шкале
- Цветовая индикация состояний (зеленый/желтый/красный/серый)
- Интерактивная шкала с возможностью масштабирования
- Поддержка различных масштабов (час, день, неделя, месяц)
- Tooltips с детальной информацией о каждом событии

#### 2.2.2. Фильтрация
- Фильтрация по периоду времени (date picker)
- Фильтрация по конкретному сервису или группе сервисов
- Фильтрация по типу состояния
- Сохранение фильтров в URL (для возможности поделиться ссылкой)

#### 2.2.3. Аналитика
- Расчет метрик доступности (uptime/downtime)
- Статистика по типам состояний
- Графики трендов
- Экспорт отчетов (PDF, CSV)

### 2.3. Real-time обновления

#### 2.3.1. SignalR интеграция
- Подключение к SignalR hub `/hubs/status`
- Подписка на обновления конкретных сервисов
- Подписка на обновления всех сервисов
- Автоматическое переподключение при разрыве соединения
- Индикатор статуса подключения

#### 2.3.2. Обновление UI
- Автоматическое обновление данных при получении событий
- Плавные анимации при изменении состояний
- Уведомления о критических изменениях (опционально)

### 3.3. API интеграция

#### 3.3.1. Конфигурация API URL
API URL должен быть настраиваемым параметром через переменные окружения для поддержки разных окружений (Development, Staging, Production).

**Переменная окружения**: `VITE_API_URL` (для Vite) или `REACT_APP_API_URL` (для Create React App)

**Значения по умолчанию для разных окружений**:
- **Development**: `https://localhost:7213`
- **Staging**: Настраивается через переменные окружения
- **Production**: Настраивается через переменные окружения

**Пример использования в коде**:
```typescript
// config/api.ts
const API_URL = import.meta.env.VITE_API_URL || 'https://localhost:7213';

export const apiClient = axios.create({
  baseURL: API_URL,
  headers: {
    'Content-Type': 'application/json',
  },
});
```

**Пример файла `.env.development`**:
```env
VITE_API_URL=https://localhost:7213
```

**Пример файла `.env.production`**:
```env
VITE_API_URL=https://api.x-lab.by
```

**Примечание**: 
- Для Vite используются переменные с префиксом `VITE_`
- Для Create React App используются переменные с префиксом `REACT_APP_`
- Переменные должны быть объявлены до сборки приложения
- В production сборке переменные встраиваются в код во время сборки

#### 3.3.2. API клиент
- Базовый URL из переменных окружения (см. раздел 3.3.1)
- Interceptors для:
  - Добавления JWT токена в заголовки
  - Обработки ошибок (401, 403, 500 и т.д.)
  - Автоматического обновления токена при 401
- Типизация всех API ответов через TypeScript

#### 3.3.3. SignalR конфигурация
SignalR hub URL должен формироваться на основе базового API URL.

**Пример конфигурации**:
```typescript
// config/signalr.ts
const API_URL = import.meta.env.VITE_API_URL || 'https://localhost:7213';
const SIGNALR_HUB_URL = `${API_URL}/hubs/status`;

export const signalRConnection = new signalR.HubConnectionBuilder()
  .withUrl(SIGNALR_HUB_URL)
  .build();
```

## 6. Требования к развертыванию

### 6.1. Окружения
- **Development** - локальная разработка
- **Staging** - тестовое окружение
- **Production** - рабочее окружение

### 6.2. Конфигурация

#### 6.2.1. Переменные окружения
Проект должен поддерживать конфигурацию через переменные окружения для разных сред разработки.

**Структура файлов окружения**:
- `.env` - общие переменные (не коммитится в репозиторий)
- `.env.development` - переменные для разработки (не коммитится)
- `.env.production` - переменные для production (не коммитится)
- `.env.example` - пример конфигурации (коммитится в репозиторий)

**Пример `.env.example`**:
```env
# API Base URL
VITE_API_URL=https://localhost:7213

# SignalR Hub URL (опционально, по умолчанию формируется из VITE_API_URL)
# VITE_SIGNALR_HUB_URL=https://localhost:7213/hubs/status
```

**Пример `.env.development`**:
```env
VITE_API_URL=https://localhost:7213
```

**Пример `.env.production`**:
```env
VITE_API_URL=https://api.x-lab.by
```

**Важные замечания**:
- Все чувствительные данные должны храниться в переменных окружения
- Файлы `.env*` (кроме `.env.example`) должны быть в `.gitignore`
- Переменные с префиксом `VITE_` доступны в клиентском коде
- Не храните секреты (токены, пароли) в переменных с префиксом `VITE_` - они будут видны в bundle

#### 6.2.3. Настройка переменных окружения в Vercel
При деплое на Vercel переменные окружения настраиваются через панель управления Vercel или через CLI.

**Через панель управления Vercel**:
1. Перейти в Settings → Environment Variables
2. Добавить переменные для соответствующих окружений (Production, Preview, Development)
3. Указать значения:
   - `VITE_API_URL` - базовый URL API
   - `VITE_SIGNALR_HUB_URL` (опционально) - URL SignalR Hub

**Через Vercel CLI**:
```bash
vercel env add VITE_API_URL
vercel env add VITE_SIGNALR_HUB_URL
```

**Пример значений для Production в Vercel**:
```
VITE_API_URL=https://api.x-lab.by
```

**Пример значений для Preview (Staging) в Vercel**:
```
VITE_API_URL=https://api-staging.x-lab.by
```

**Важно для Vercel**:
- Переменные окружения применяются при сборке проекта
- После добавления/изменения переменных окружения необходимо пересобрать проект
- Vercel автоматически пересобирает проект при пуше в основную ветку (Production)
- Для Preview окружений (pull requests) используются переменные Preview окружения

#### 6.2.2. Настройка сборки для разных окружений
- Использование режимов сборки (development, production)
- Автоматическая подстановка переменных окружения при сборке
- Оптимизация production сборки (минификация, tree-shaking)
- Source maps для development, отсутствие source maps для production

### 6.3. Деплой на Vercel

#### 6.3.1. Платформа деплоя
Frontend приложение размещается на платформе **Vercel** - сервисе для деплоя фронтенд приложений.

**Преимущества Vercel**:
- Автоматический деплой из Git репозитория
- Глобальный CDN для быстрой загрузки
- Автоматическое масштабирование

- Автоматический HTTPS

#### 6.3.2. Конфигурация проекта для Vercel

**Файл `vercel.json` (опционально)**:
```json
{
  "buildCommand": "npm run build",
  "outputDirectory": "dist",
  "devCommand": "npm run dev",
  "installCommand": "npm install",
  "framework": "vite",
  "rewrites": [
```

**Структура проекта**:
- Root directory: корень проекта (где находится `package.json`)

#### 6.3.3. Процесс деплоя

#### 6.3.4. Настройка роутинга для SPA
Vercel автоматически настраивает редирект всех маршрутов на `index.html` для поддержки client-side routing React Router.

**Настройка через `vercel.json`**:
```json
{
  "rewrites": [
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

**Альтернативно**, можно использовать файл `vercel.json` с более детальной настройкой:
```json
{
  "rewrites": [
    {
      "source": "/api/(.*)",
      "destination": "/api/$1"
    },
    {
      "source": "/(.*)",
      "destination": "/index.html"
    }
  ]
}
```

#### A.1. Конфигурация API клиента (Axios)
```typescript
// src/config/api.ts
import axios from 'axios';

const API_URL = import.meta.env.VITE_API_URL || 'https://localhost:7213';

export const apiClient = axios.create({
  baseURL: API_URL,
  headers: {
    'Content-Type': 'application/json',
  },
});

// Interceptor для добавления токена
apiClient.interceptors.request.use((config) => {
  const token = localStorage.getItem('accessToken');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

// Interceptor для обработки ошибок
apiClient.interceptors.response.use(
  (response) => response,
  async (error) => {
    if (error.response?.status === 401) {
      // Логика обновления токена или редиректа на login
    }
    return Promise.reject(error);
  }
);
```

#### A.2. Конфигурация SignalR
```typescript
// src/config/signalr.ts
import * as signalR from '@microsoft/signalr';

const API_URL = import.meta.env.VITE_API_URL || 'https://localhost:7213';
const SIGNALR_HUB_URL = import.meta.env.VITE_SIGNALR_HUB_URL 
  || `${API_URL}/hubs/status`;

export function createSignalRConnection(): signalR.HubConnection {
  return new signalR.HubConnectionBuilder()
    .withUrl(SIGNALR_HUB_URL)
    .withAutomaticReconnect({
      nextRetryDelayInMilliseconds: (retryContext) => {
        if (retryContext.previousRetryCount < 10) {
          return 1000 * Math.pow(2, retryContext.previousRetryCount);
        }
        return 60000; // Максимальная задержка 60 секунд
      },
    })
    .build();
}
```
